# VRhotspot v1.1.0-rc4 — Developer Hub

This is the release where VRhotspot stops being just a fast dedicated network
and becomes the Linux VR development workflow I wanted to exist.

The normal Quest setup is now:

1. Plug the headset in over USB.
2. Approve USB debugging.
3. Open Developer Hub and select **Set up wireless headset**.
4. VRhotspot moves the Quest to the dedicated network, verifies it, enables
   wireless ADB, and finishes the connection.
5. Unplug the cable and keep working.

No typing IP addresses. No permanent pairing-code forms. No copying ADB
commands. No opening the headset Wi-Fi settings during the normal flow.

If Horizon OS refuses automatic enrollment, Developer Hub does not pretend it
worked. It falls back to clear manual instructions, privacy-aware credential
assistance, and automatic rechecks until the headset is actually on the correct
network.

## The big addition: automatic Quest Wi-Fi enrollment

Developer Hub now uses authorized USB ADB to connect the Quest directly to the
active VRhotspot network. Horizon OS does not advertise the working
`connect-network` command correctly, so VRhotspot attempts it directly instead
of trusting the incomplete help output.

A successful command is not enough. VRhotspot waits until it can prove all of
the following:

- the SSID exactly matches the active VRhotspot network;
- `wlan0` has a valid address inside the configured hotspot subnet;
- the gateway matches the configured VRhotspot gateway;
- the default route uses `wlan0`;
- the route source belongs to the hotspot subnet.

Only after that verification does VRhotspot enable wireless ADB and connect to
the verified headset address. The entire flow fails closed on another network.

## Developer Hub is now a real development surface

- Guided USB-to-wireless headset setup
- Automatic Quest network enrollment with a manual fallback
- Managed Android Platform-Tools installation and repair
- System ADB detection and guarded removal on supported mutable systems
- Connected-device overview and identity
- APK upload, install, launch, stop, clear-data, and uninstall controls
- Wireless ADB handoff that survives USB removal
- User-facing status instead of raw ADB state strings

## Desktop companion and portal

The optional Flatpak companion now has the Web Portal built in, shares its
authenticated browser session with the tray, and gives you the same controls
without turning the desktop app into a second implementation of the product.

Basic and Pro modes also share one hotspot lifecycle now. Starting, Running,
Stopping, Stopped, Restarting, Repairing, and error states no longer contradict
one another, and the Wi-Fi icon follows the real service state.

## Security and privacy

I wanted this to become easier without making it careless.

- The browser never sends the hotspot password during automatic setup.
- Wireless ADB is never enabled until the dedicated network is verified.
- Hotspot credentials stay redacted from normal configuration responses, logs,
  diagnostics, and support bundles.
- Privacy Mode keeps manual credentials out of the DOM until the user explicitly
  asks to see them.
- ADB and package-management operations use fixed argument arrays with
  `shell=False`.
- System ADB removal is limited to recognized packages and refused on immutable
  systems such as SteamOS and Bazzite.

## Real-hardware validation

The complete GUI workflow was tested on a real Quest 3S connected to a CachyOS
host:

- Quest started on another Wi-Fi network;
- Developer Hub automatically moved it to `VR-Hotspot`;
- WPA authentication and DHCP completed;
- VRhotspot verified the SSID, subnet, gateway, interface, and route;
- wireless ADB connected;
- the headset remained available after the USB cable was removed.

The portal was also used remotely from SteamOS through an SSH tunnel. GitHub
Actions validates the full Python suite on Python 3.11, 3.12, and 3.13, along
with Ruff, compileall, ShellCheck, DOM integration, lifecycle tests, vendor/SBOM
checks, the Platform-Tools pin, and the installer matrix.

## Install

Download the installer first, then run it locally:

```bash
curl -sSL https://raw.githubusercontent.com/josethevrtech/VRhotspot/main/install.sh -o /tmp/vrhotspot-install.sh
sudo bash /tmp/vrhotspot-install.sh
```

SteamOS users should continue downloading the installer first instead of piping
it directly into bash.

## Upgrading an existing install

Run the same installer again. It preserves the runtime configuration and
refreshes the daemon, portal, desktop integration, and service files.

## Why this is still an RC

This is intended to be the final public validation build before stable
v1.1.0. The core Quest 3S workflow works end to end on real hardware. RC4 is for
clean-install and distro validation, not another round of feature additions.

The next release from this line should be stable **v1.1.0** unless a real
release-blocking issue is found.
